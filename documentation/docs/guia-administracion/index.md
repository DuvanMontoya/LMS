# Guía de administración

La administración institucional no equivale al operador global de plataforma. Las acciones se autorizan por capacidades de la membresía y quedan sujetas a políticas y servicios de dominio.

## Operación institucional

Un propietario puede gestionar personas, invitaciones, perfiles institucionales, ajustes de membresía, sesiones administradas e integraciones. El último propietario activo no puede perderse por una operación de revocación, suspensión o terminación.

Un administrador opera el currículo, períodos, grupos, cohortes, matrículas, releases aprobados, agenda y entregas. No obtiene de ello permiso para editar autoría, aprobarla o alterar calificaciones.

## Acciones sensibles

| Acción | Efecto |
| --- | --- |
| Suspender o terminar una membresía | Deniega acceso futuro sin borrar el historial institucional. |
| Retirar una publicación | Impide entrega según la política sin reescribir el release inmutable. |
| Archivar currículo o estructura | Conserva identidad e historia; las posiciones activas se ajustan mediante servicio transaccional. |
| Revocar una sesión | Obliga a autenticarse otra vez sin exponer la cookie. |
| Recalificar | Crea versiones nuevas de calificación; no sobrescribe evidencia previa. |

## Gestión de recursos y sesiones

Los recursos se cargan en cuarentena y sólo se usan tras el procesamiento. No trate una carga como disponible hasta que su versión esté `READY`. Las clases en vivo y grabaciones usan políticas de organización, grupo y ventana; nunca publique tokens de LiveKit ni URL de grabaciones.

## Auditoría y recuperación

Los cambios de membresía, autoría, publicación, aprendizaje, notas y eventos están diseñados para conservar historia. Para investigar un incidente, consulte los registros operativos y los runbooks del repositorio. No borre datos históricos para resolver una inconsistencia: determine el servicio y estado que la produjo.
